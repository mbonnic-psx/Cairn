# Tasks: The notebook in the landscape — slice `protection-page`

**Input**: `slices/protection-page/plan.md`, `research.md` (P1–P6), `data-model.md`, `quickstart.md`, `contracts/ui-shell.md` ("Knowing it is on a page", "Headings", "Look tokens"); `decisions.md` D6–D10; spec US3 (Protection, What is protected), FR-016, FR-018, FR-020, FR-021, FR-022, FR-025, FR-031, SC-009 and the Clarifications block "Gaps reviewed for slice `protection-page`". Carried: frame T025 (T003 below).
**Scope**: US3 for two screens only, Protection and What is protected (`Trail`), plus the two things every later page slice builds on: the "on a notebook page" context (D6) and the heading outline (D9). No other screen is touched; Current is unchanged element for element (SC-009).
**Method**: Every task is one RED-GREEN-REFACTOR increment cut on one rule, with its examples. Write the failing test, watch it fail for the reason the task names, make it pass, tidy, commit. There is no example map or `model.yaml` for this slice, so rules are cut from the spec's scenarios and FRs, D6–D9 and research P1–P6. No mocking framework and no new `vi.mock`: screen tests render the screen with props (as `Protection.test.tsx` does) inside `NotebookShell` or `notebookPageContext`'s provider; the App-level test stands in at the IPC seam with a fake `window.__TAURI_INTERNALS__.invoke` written in the test tree (research P4). A proof that would pass the moment it is written is folded into the task that produces the behaviour it guards: "words identical to Current" is asserted inside each state task (T004–T006, T007) by comparing the spread's text with the same state rendered outside any shell, not as a separate sweep task that has no GREEN.
**Guard**: Existing tests under `src/screens/__tests__/` are never edited and stay green after every task (SC-009). `src/shell/__tests__/AppLook.test.tsx`, including its production-equals-Current test, stays green and unedited. The one existing test this slice changes is "is called "Cairn" once" in `src/shell/__tests__/NotebookShell.test.tsx`, and only as research P2 says (T003). Every task ends with `npm test` green.
**Manifests**: each task lists the files it may touch. Tasks whose lists are disjoint may run side by side.
