# Tasks: The notebook in the landscape — slice `looks`

**Input**: `slices/looks/plan.md`, `research.md` (L1–L5), `data-model.md`, `quickstart.md`, `contracts/ui-shell.md`; `decisions.md` D3 and D4; spec FRs cited in `story-split.md` row 2.
**Scope**: US2 only: FR-009, FR-010, FR-011, FR-012 (held, not rebuilt), FR-013, FR-013b, FR-016, FR-021, FR-022 as it bears on the night sky, FR-023, FR-033. Midday, night, the four-choice switch and the greeting's words per look. No page screen is touched.
**Method**: Every task is one RED-GREEN-REFACTOR increment cut on one rule, with its examples. Write the failing test, watch it fail for the reason the task names, make it pass, tidy, commit. No example map or `model.yaml` exists for this slice, so rules are cut from the spec's acceptance scenarios, FRs, decisions D3 and D4 and research L1–L5. No mocking framework: tests that render `NotebookShell`, `Greeting`, `Landscape`, `LookSwitch` take props directly; the `App`-level tests reuse the `devBuild` prop and the ipc stubbing `AppLook.test.tsx` already carries. A proof that would pass the moment it is written is folded into the task that produces the behaviour it guards (FR-033 and the greeting-over-sky pairs ride with each look's tokens; the no-transition guard rides with T005).
**Guard**: the existing tests under `src/screens/__tests__/` are never edited; existing tests under `src/look/__tests__/` and `src/shell/__tests__/` are edited only where a task names the file and the rule that changes. Every task ends with `npm test` green.
**Manifests**: each task lists the files it may touch. Tasks whose lists are disjoint may run side by side.
